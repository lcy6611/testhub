# 使用阿里云镜像仓库部署 Dify

你已在阿里云创建镜像仓库（如 **testhub-lcy**），可按下面步骤使用。

---

## 一、登录阿里云镜像仓库

在**本机**打开 CMD 或 PowerShell，执行登录命令：

```bash
docker login --username=你的阿里云主账号名 你的仓库公网地址
```

**注意：**
- **地址只填域名**，不要加 `/命名空间/仓库名`。例如：`crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com`。
- **本机（家里/公司电脑）请用「公网地址」**；只有在阿里云 ECS 且与镜像仓库同地域时，才用「专有网络地址」（带 `-vpc.` 的域名）。
- 示例（公网）：`docker login --username=lcy2020026128 crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com`

按提示输入**镜像仓库密码**（在阿里云控制台「访问凭证」里查看或修改）。出现 `Login Succeeded` 即表示登录成功。

---

## 二、两种常见用法

### 用法 1：只推送你自己构建的镜像

若你本地已经构建了某个镜像（例如自己的应用）：

```bash
# 给镜像打上阿里云地址的标签（把 ImageId、镜像版本号 换成实际值）
docker tag [你的镜像ID或名称] crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com/testhub-lcy/testhub-lcy:v1

# 推送到阿里云
docker push crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com/testhub-lcy/testhub-lcy:v1
```

之后在任意能访问阿里云的机器上执行：

```bash
docker pull crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com/testhub-lcy/testhub-lcy:v1
```

即可拉取该镜像。

---

### 用法 2：把 Dify 整套镜像迁到阿里云（解决无法访问 Docker Hub）

在**能访问 Docker Hub 的机器**上，把 Dify 用到的镜像先拉到本地，再打标签推到你的阿里云仓库，这样在**无法访问 Docker Hub 的机器**上就可以从阿里云拉取并部署。

**步骤概览：**

1. **在能上外网的机器上**  
   - 进入 Dify 的 docker 目录：`cd dify-main\docker`（或 `deploy\dify-repo\docker`）  
   - 执行：`docker compose pull`，拉齐所有 Dify 镜像  
   - 执行：`docker compose config --images`，查看本 compose 用到的镜像列表  

2. **在阿里云控制台**  
   - 为每个要迁移的镜像各建一个「镜像仓库」（或使用同一命名空间下不同仓库名），例如：  
     `dify-api`、`dify-web`、`dify-nginx`、`postgres`、`redis` 等（名称可与原镜像对应，便于记忆）  

3. **对每个镜像执行 tag + push**（示例）  
   - 登录（同上）：  
     `docker login --username=你的用户名 你的仓库公网地址`  
   - 示例（以 dify-api 为例，请把版本号换成你实际拉取的 tag）：  
     ```bash
     docker tag langgenius/dify-api:1.12.1 crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com/testhub-lcy/dify-api:1.12.1
     docker push crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com/testhub-lcy/dify-api:1.12.1
     ```  
   - 对其余镜像（dify-web、nginx、postgres、redis、weaviate 等）重复类似操作，只是把镜像名和 tag 换成 `docker compose config --images` 里列出的那一项。  

4. **在无法访问 Docker Hub 的机器上**  
   - 用同一账号执行一次：  
     `docker login --username=你的用户名 你的仓库公网地址`  
   - 修改 Dify 的 **docker-compose 文件**（或通过 .env 覆盖）：把其中所有 `image: xxx` 的地址，改成你在阿里云的地址，例如：  
     `crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com/testhub-lcy/dify-api:1.12.1`  
   - 在该机的 `dify-main\docker` 下执行：  
     `docker compose up -d`  
   - 此时会从**阿里云**拉取镜像，不再访问 Docker Hub。

**说明**：Dify 的 compose 里镜像较多（api、web、worker、nginx、postgres、redis、weaviate 等），需要逐个在阿里云建仓并 push；若你希望，我可以根据你当前 `dify-main/docker` 里的 compose 列出一份「镜像名 → 建议的阿里云仓库名」对照表，方便你批量建仓和写 tag/push 命令。

---

## 三、使用专有网络地址（可选）

若部署机器是**阿里云 ECS** 且与镜像仓库在同一地域，可在登录和 pull/push 时使用控制台里的**专有网络（VPC）地址**，速度更快且不占公网流量：

- 将上述命令里的  
  `crpi-hr6f2vrzv7uqdl2t.cn-qingdao.personal.cr.aliyuncs.com`  
  换成  
  `crpi-hr6f2vrzv7uqdl2t-vpc.cn-qingdao.personal.cr.aliyuncs.com`  
  再执行 `docker login` 和 `docker pull`/`docker push`。

---

## 四、小结

| 目的 | 操作 |
|------|------|
| 登录 | 使用控制台「操作指南」里的 `docker login` 命令 |
| 推送自己的镜像 | `docker tag` → `docker push`（镜像地址用你的公网地址 + 仓库名 + tag） |
| 从阿里云拉取 | `docker pull 你的公网地址/命名空间/仓库名:tag` |
| 把 Dify 迁到阿里云 | 在可访问 Docker Hub 的机器上 pull → tag 为阿里云地址 → push；在无外网机器上改 compose 镜像地址后 `docker compose up -d` |

你的**公网地址**、**命名空间/仓库名**以阿里云控制台「基本信息」和「操作指南」为准，把本文中的示例地址替换成你自己的即可。
